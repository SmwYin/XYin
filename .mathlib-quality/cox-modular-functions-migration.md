# Cox migration to bundled modular functions

Date: 2026-09-21. User-authorized scope: adopt the shared modular-function definition in
Cox's function-field proofs and remove redundant Cox implementations.

## Result and mathematical scope

- `Cox.theorem_11_9_i` now takes `f : ModularFunction 𝒮ℒ`.
- `Cox.theorem_11_9_ii_pointwise` takes a bundled `ModularFunction (Gamma0 N)`.
- `Cox.levelJModularFunction` bundles `j(Nτ)`, and Cox-product coefficients are bundled
  by `coxPhiFunction_coeff_modularFunction` using their holomorphy.
- `UpperHalfPlaneFunctionField.FunctionField` is definitionally the shared
  `UpperHalfPlane.MeromorphicField`, with no legacy holomorphic fraction-field model.
- `modularRepresentatives N` is exactly the range of `ModularFunction.toMeromorphicField`.
  As in the prior architecture, `gamma0ModularFunctionField` is the subfield generated by
  these images over the embedded `ℂ(j)`. Theorem 11.9(ii) equates this generated subfield
  with `ℂ(j)(j_N)`. It does not separately assert that its carrier equals the image.
- `toMeromorphicField_eq_ratFunc` supplies an actual ambient-field equality for every
  level-one bundled modular function, and `toMeromorphicField_mem_jLevelFunctionField`
  places every bundled level-N modular function in the expected simple extension.

`CuspData` is explicitly auxiliary raw analytic proof data for pole-clearing and interpolation.
It is not a replacement definition of bundled modular functions: pointwise multiplication of
meromorphic representatives can create removable-value defects, so those intermediate
expressions cannot in general be bundled without normalization. Public classification theorems
now enter through the new bundle and derive this auxiliary data from it.

## Reuse and deletion

- Removed `Represents`, its uniqueness argument, and its fraction-representation scaffolding.
- Removed the old `FractionRing HolomorphicFunction` ambient field and fraction-field
  extension of the modular group action. Genuine germ precomposition now supplies the action.
- Removed duplicate j holomorphy/periodicity proofs from `ModularFunction`, `LatticeJ`, and
  `CoxMatrices/LaurentExpansion`.
- Removed the unused `cusp_laurent_finitePrincipalPart` wrapper, whose conclusion already
  follows from the Laurent-series coefficient API without its modularity assumptions.
- Reused the single `levelJ_mdifferentiable` theorem in construction and conjugate roots.
- Moved congruence-period/cusp constructors and general field-action infrastructure into
  `ModularFunctions/Congruence.lean` and `ModularFunctions/FieldAction.lean`.
- Updated all Cox callers of the superseded raw modular-function predicates.

Twelve Cox files changed, with a net reduction of 143 lines. Two shared library files were
added. The starting source snapshot is `/tmp/xyin-cox-before`; prior modular-function work
was preserved. No commits or external changes were made.
